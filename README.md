# Codelens_Pro · 多 Agent 代码审查与修复工作流

**MVP：编码 Agent → CodeLens 审查 Agent → 修复 Agent。** 输入需求，或上传已有 Python 单文件，查看自动修复后的完整源码、红绿差异、审查依据与可恢复的执行记录。原有 Python / C++ 只读审查入口继续保留。

## GitHub 仓库与持续集成

本目录是可独立提交的项目根目录。首次发布按 [GitHub 上传指南](docs/GITHUB_UPLOAD.md) 操作；仓库根目录应直接包含 `app.py` 和 `.github/`。

已配置 GitHub Actions：推送、Pull Request 或手动启动时，在 Windows / Python 3.12 中检查源码、执行完整测试、校验便携运行时并生成源码包。CI 不需要模型密钥；测试报告和通过检查的源码包可在该次 Actions 运行中下载。具体流程见 [CI 说明](docs/CI.md)。

## 安装与启动

使用 Windows 和 Python 3.12（本项目已验证的版本）。锁定依赖需要 Python 3.12 或更高版本；首次安装需要网络。

1. 将本目录完整解压到可写文件夹。
2. 双击 `install.cmd`，等待安装完成。
3. 双击 `start.cmd`，打开 [本地应用](http://127.0.0.1:8503)。

启动入口已兼容 Windows 中文及空格路径。若 8503 已有服务，可直接打开上面的地址；需要另开端口时，在终端运行 `start.cmd -Port 8504`。排查启动问题可运行 `start.cmd -CheckOnly`；它只检查文件和依赖，不启动服务。`install.cmd -CheckOnly` 也不会安装或联网。

也可以在本目录运行：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt -c requirements-lock.txt
.\.venv\Scripts\python.exe -m streamlit run app.py --server.address 127.0.0.1 --server.port 8503
```

## 第一次体验

选择“流程演示（无需密钥）”，选择“订单修复闭环”，点击“载入当前场景示例”，再通过“从需求生成”入口开始运行。保持默认“仅静态检查”即可体验。演示用固定角色产物配合实际本地检查，展示“编码 → 审查 → 修复 → 再审查”的状态与代码变化。它不调用语言模型，也不代表模型能力实测。

在“任务示例与验收合同”可选择订单统计、文本统计等 10 种合成纯函数任务。订单和文本统计带“可演示”标记；其他合同或自定义需求使用真实模型。加载样例后合同保持绑定；需要完全自定义目标时可“解除内置合同绑定”。

代码工作区默认并排显示“修改前 / 修改后”：左侧红色表示删除，右侧绿色表示新增，未变行保持中性色。可对比首次源码、最近一轮修复前版本或指定历史版本。修复直接更新应用内当前源码；完整代码与原始快照可展开查看，下载按钮导出当前版本。演示模式的修复适用于内置订单和文本统计缺陷样例，未知业务源码不会被演示脚本任意改写。

“上传 / 粘贴代码”从已有 Python 代码进入审查与修复，编码角色显示无需执行。上传内容在应用内创建版本，不会覆盖用户原文件。

可选“首次检查通过”和“修复无进展”查看其他分支。勾选“首次审查后暂停”后，可以从“历史运行”打开记录并点击“继续此任务”，观察已提交的编码不会重复执行。

若修复没有产生实质代码变化，页面直接显示未生效提示、修复 Agent 的说明及未解决项。对于已结束且有当前版本修复目标的记录，可点击“按审查意见重新修复”：它保留目标、源码与历史，建立关联的新任务，使用明确的新修复轮数和新预算；旧记录与旧用量仍可追溯。新版本仍须重新审查和验证。

## 编排、进度与证据

“可视化流程编排”通过节点按钮选择角色，再配置顺序或并行检查、修复循环、0～2 轮上限及首次审查后暂停。计划随运行保存并实际改变路由；这是基于模板的可视编辑；可选择已注册的扩展 Agent，不支持任意拖拽、连线或上传插件代码。

并行模式会同时执行审查和独立验收，等待汇合后再决定是否修复；页面展示同版本分支的起止时间及实际重叠。执行中的高亮是临时开始/结束通知，结果以提交后的源码、审查及验收记录为准。关联重试的用量分为本轮、继承来源和已记录合计。

“问题 / 失败用例 → 修复版本 → 重新验收”按问题或用例 ID 和源码版本定位证据、关联修改块与复验结果；模型声明处理、复查未再检出、功能用例通过分别展示。可下载当前完整源码和 Markdown 运行报告；完整 JSON 快照由运行服务提供，本地 CLI 演示也会保存 JSON。

## 真实模型

在侧栏选择“真实模型”，填写自己的 DeepSeek API Key、接口地址和可用模型名称。也可复制 `.env.example` 为 `.env`，自行配置；不要将 `.env` 放进提交包。模型名称请使用账户实际支持的值。

真实模式会将任务、源码及相关审查上下文发送到配置的模型服务，并产生 API 费用。用户本地曾出现修复模型返回原文的失败；改进交接后，经用户明确授权的一次真实复测已保存修复版本，并通过静态检查。该任务仍有准确率效果与外部条件待确认，整体保留“需人工处理”，没有声称识别率已提升。详见验证记录，导出的业务记录不应包含 API Key。

## 验证边界

- **静态检查通过，功能待验证**：只完成语法、规则和工作流要求的检查，没有执行功能用例。
- **隔离功能验收（便携运行时）**：使用附带并校验哈希的 CPython WASI 和 Wasmtime，执行已注册合同的实际纯函数用例，无需 Docker。
- **内置订单功能验收（需 Docker）**：保留独立容器选项；本机没有完成 Docker 实测。
- **环境阻塞 / 需人工处理 / 失败**：不会被显示成成功；检查事件和错误后再恢复或修改任务。

自动编码和修复首版限定 Python 单文件。原版审查页面仍支持 Python / C++，C++ 审查不等于 C++ 编译、运行或自动修复。红绿差异表示文本变化，不表示功能正确。

便携运行时只预开解释器标准库和本次工作区的只读目录，限制时间、指令、内存与输出；不在宿主 Python 导入候选源码。它用于标准库纯函数，不提供 TensorFlow、摄像头或任意依赖。实际期望值留在宿主判定，工作流公开用例与评测独立审核分开。
