# 便携 Python 功能验收运行时

项目携带 CPython 3.13.15 的 WASI 归档，只有明确选择便携功能验收或运行独立评测时才使用。首次运行解压到 `data/wasi-runtime/`，不联网下载、不读取宿主环境变量。源码和本次输入放入临时目录，运行结束删除。

- 上游：[CPython WASI 构建发布](https://github.com/brettcannon/cpython-wasi-build/releases/tag/v3.13.15)
- 文件：`python-3.13.15-wasi_sdk-24.zip`
- 发布 SHA-256：`67e1c32a85d5e0600c0939f5fd4023ca0127f1a9e81f5499697467bda67af78d`
- Python 许可证：随归档及本目录 `LICENSE` 提供。
- 执行库：PyPI 的 `wasmtime==49.0.0`，见[运行库接口](https://bytecodealliance.github.io/wasmtime-py/)。

每次执行只向 WASI 提供两处只读目录：解释器标准库和该次临时工作区。不会预开用户目录，不继承密钥、网络连接或标准输入。运行受时间、指令数、256 MiB 线性内存和输出大小限制。功能预期值留在宿主判定器中，隔离程序只返回实际值、异常类型和调用后输入，不接受被测代码自报的“通过”。

可信子进程复用 Wasmtime 引擎，采用隔离模式启动及最小环境，不继承 API 凭证。父进程为每次执行设置独立的实际时间上限；即使 guest 阻塞在宿主调用，超时也会终止该子进程，下一次请求重新建立。首次解压、校验与模块编译属于启动阶段，另有 20 秒上限，并纳入工作流总活动耗时。验证记录保留执行后端及解释器归档哈希。

这是面向标准库纯函数任务的功能验收环境。它不提供 TensorFlow、摄像头、任意外部依赖或系统级行为测试；此类代码仍可静态审查与修复。WebAssembly 隔离运行时仍需正常的依赖维护，项目不声称能够证明任意程序安全或正确。

隔离保障和评测防作弊是不同边界：调用包装器和候选函数运行在同一个 guest Python 进程，刻意使用反射、读取包装器或伪造实际值协议的对抗程序可能干扰测量。随机输出标识用于避免普通日志混入，不是 guest 内部的秘密。本轮任务集用于正常生成代码的功能回归，不宣称是不可作弊的评判器。
