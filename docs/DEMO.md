# 1 分钟以内的展示脚本

建议先安装依赖、启动应用并确认本机离线示例可运行，再开始录制。视频中的“演示模式”标签应始终可见，避免将固定场景误称为真实模型输出。

| 时间 | 操作 | 可口述内容 |
|---|---|---|
| 0–8 秒 | 展示两个入口、节点按钮与流程图，选并行检查 | “三个角色按任务协作；模板设置会改变实际路由。” |
| 8–18 秒 | 载入订单演示，选择便携隔离验收并开始 | “这里使用固定角色响应，不调用真实模型；功能用例由真实隔离 Python 执行。” |
| 18–30 秒 | 展示运行卡片、审查与验收汇合、修复 | “正在执行是临时通知，只有提交后的版本与结果才作为证据。” |
| 30–43 秒 | 展示左红右绿，选择“问题 → 修改 → 复查”中的问题 | “问题绑定原版本；模型声明、新版本复查和功能用例结果分开展示。” |
| 43–52 秒 | 展示终态、验收记录与分支重叠时间 | “公开合同用例已实际执行；通过范围以这些用例为准。” |
| 52–59 秒 | 展示 Markdown 报告下载与本轮/来源用量 | “源码、报告和历史都可追踪，关联重试会单独记新预算。” |

如果希望展示恢复，可先开启“首次审查后暂停”，在第 18–32 秒点击“继续此任务”，再展示修复。暂停完成时不要将它称为服务崩溃恢复实验。

录制前先让便携运行时完成首次校验与解压，并运行一次同样的公开样例。若选择“仅静态检查”，把终态口述改为“静态通过，功能尚未执行”。可视编辑是节点点选与模板选项，不要称为自由拖拽编排器。

也可单独录制失败处理：选择“修复无进展”，展示直接可见的未生效提示、模型说明和未解决项，演示模式只展示停止证据，不提供真实模型重试按钮。“按审查意见重新修复”仅在真实模型的合适终态出现，会新建关联任务并使用新预算；不得把再次点击按钮称为修复成功。

本机 Docker 尚未实测，视频使用已跑通的便携 WASI 档位。真实模型展示只能采用实际记录：本轮 8 个真实场景中，需求生成两例首稿正确，合法跳过修复；不存在一条真实需求生成中同时执行三个角色的记录，不能用离线固定响应代替它。可选择真实上传修复记录展示审查→修复协作，或者明确展示真实生成→审查的首次通过分支。

8 场景中 7 个可评估功能场景最终通过、1 个效果未知场景合理停机，是有限合成任务结果；不得声称通用正确率 100%、识别率已提高或保证得到 100 分。公开视频仅使用合成样例，不展示用户私人源码、密钥或个人运行报告。

## 新版展示补充

在编排中选入“验收解读 Agent”，用运行图展示真实路径、节点耗时与执行次数。点击节点可查看每轮交接。问题选择器包含 `V-` 失败用例，展示旧失败 → 真实新版本 → 同用例实际重验；演示订单的初始缺陷先被静态规则拦截，若要展示功能失败用例，请打开真实配对实验中的 clamp 修复记录。
